# План: CRM для нескольких транспортных компаний

**Решение (14.11.2026):** отдельный экземпляр на компанию — свой проект Supabase и свой
проект Vercel, один общий код в этом репозитории. Цель — 20+ компаний за год.

## Почему так

| | A. Экземпляр на компанию (выбрано) | B. Общая база (`company_id`) |
|---|---|---|
| Утечка данных между компаниями | невозможна: разные базы | любой пропущенный фильтр в ~88 файлах на `service_role` |
| Объём работы до первого клиента | 1–2 недели | 1–2 месяца+ |
| Миграции | на каждую базу — нужен скрипт | одна база |
| Подключение клиента | скрипт (позже — по кнопке) | регистрация |
| Supabase | ~$10/мес за доп. проект в одной Pro-организации | один проект |

20 компаний на A ≈ $25 (Pro) + 20 × $10 (Micro) − $10 (кредит) ≈ **$215/мес** за Supabase.
Перепроверить цены на supabase.com/pricing перед расчётом тарифа для клиентов.
Vercel: коммерческое использование — тариф Pro (Hobby — только некоммерческий), уточнить условия.

**Точка пересмотра — 10 клиентов.** Если раскатка миграций и поддержка N баз станут узким
местом — переход на B. К этому моменту этап 0 и перевод страниц с `service_role` на RLS-клиент
(очередь из `AGENTS.md`) сделают B заметно безопаснее.

## Порядок работ

1. **0.1** — схема прода (нужна выгрузка от вас, см. ниже).
2. **0.2** — настройки компании.
3. **1.1** вручную → подключить первого стороннего клиента.
4. **1.2** до второго клиента.
5. **Этап 2** параллельно с продажами.

### Что нужно от вас для 0.1
Выгрузка **только схемы** (без данных) в терминале на своём компьютере:

```
npx supabase db dump --db-url "postgresql://postgres.[ref]:[пароль]@[host]:5432/postgres" -f schema.sql
```

Строка подключения: Supabase → Project Settings → Database → Connection string → URI.
Если `supabase db dump` попросит Docker — подойдёт `pg_dump --schema-only` из PostgreSQL 16+.
Пароль в чат не присылать — только готовый `schema.sql`.
